# 石器时代 / 疯狂原始人 私服调研报告

调研时间：2026-10-26
调研目标：摸清可获得的版本、代码来源与部署方案，为“自己搭一台单机/小范围私服”选型。
调研范围：GitHub、私服发布网、藏宝湾/脚本王/游戏藏宝阁、WeLoveSA 论坛、Docker 方案、版权背景。

> 一句话结论：**石器时代有大量泄露的完整 C 服务端和客户端源码，2.5 与 8.0/8.5 都能真正跑起来；疯狂原始人 Online（2002 华义 PK 分支端游）只有论坛流传的 2.0 服务端包，没有公开源码，也没有可下载的客户端。**
> 部署难度不在“有没有端”，而在 32 位老代码、GB2312 编码、老 MySQL 依赖和 Windows 客户端。

> **如果你要的是 2002 年那款 PK 分支端游，直接看专项报告：[疯狂原始人Online-专项调研与落地方案.md](./疯狂原始人Online-专项调研与落地方案.md)。本文第 1、5 节给出背景，专项报告给出完整版本史、资源位置和分阶段执行清单。**

## 1. 先澄清两个“疯狂原始人”

网上同名但完全不同的东西，选型前必须分清：

| 名称 | 性质 | 现状 | 私服可行性 |
| --- | --- | --- | --- |
| **疯狂原始人 Online（2002）** | 华义基于石器时代做的 **纯 PK 分支端游**，把 PK 战斗单独拆成一款网游 | 官方早已停运；2002-05-01 上线当天 6000 人 | 有论坛流传的“疯狂原始人 2.0 服务端 + 配套 DATA + 登录器”整包，本质仍是 saac/gmsv 体系；没有公开源码 |
| **疯狂原始人（2019 手游）** | 天象互动开发、梦工厂电影 IP 授权的 3D 回合手游 | 已停运/换皮为《最后的原始人》等 | 全套服务端多为求购状态，没有稳定公开的一键端；和端游端不通用 |
| **疯狂原始人 2（2021）** | 电影续作 IP 手游 | 运营中 | 另有商业私服，但和石器端游无关 |

**你说的就是第一个：2002-05-01 上线、2004-07-30 停服的纯 PK 端游。** 它由华义基于石器时代自行开发，官方只出过 1.0 和 2003-01-12 的 2.0；2.0 加入蒙奇、鲁比、3-3 魔法戒指、青龙 MP 攻击等宠物技能和战绩面板，人物是 500 点自由配点、每场 PK 后可重配。它和石器共用 `saac`/`gmsv`/MySQL 架构，但版本早于 2.5，**协议、DATA、DB 都不同，不能拿 2.5 或 8.0 的端直接配**。

2013 年后私服圈还出现过标“疯狂原始人 3.0”的版本，不是官方版本号。今天仍在开的“疯狂原始人”服，多数其实是 2.5 无职业 PK 服换皮，配点仍是 20 点，并非原版机制——选型时要分清。

## 2. 石器时代版本谱系（官方）

官方版本本身就是选型依据，因为服务端源码按版本分化：

- 1.0 / 1.82：最原始，玩法极简，1.82 是后来“练极品人”任务链的起点。
- 2.0 家族开拓史、**2.5 精灵王传说**：2.5 加入转生与大量经典宠物，是公认的 **PK 平衡与私服主流版本**。
- 3.0 伊甸新大陆、4.0 新九大家族、5.0 宠物进化史、6.0 海贼王遗迹、7.0 石头就业所、7.5 精灵的召唤：逐步加入职业、装备位、二转宠、六转人。
- 8.0 失落的世界：大陆改名《新石器时代》，加入宠物装备、导师、任务日志、回炉、签到。
- 8.5 魔域大冒险：台服最后版本，大陆未更新到 8.5 即停服。魔域地图、讨伐积分、日常任务、荣誉商城。
- 9.0 黑石圣域：胜思时期的魔改续命版本，非 JSS 原版。

**私服生态的实际流行度**（据 2026-10 发布网抽样）：2.5 无职业 PK 服最多，其次是 8.5 带职业、6.0、3.0；大量服标榜“有挂/内挂”“一机五控”“三端互通”“养老服”。这说明两件事：

1. 2.5 是稳定性和 PK 体验的最优解，也是代码最干净的一支。
2. 8.0/8.5 内容多但扩展性差、端不完整，常见“开了又转回 2.5”。

### 3.3 客户端资源

- [99ds.com](https://99ds.com)：同时提供 **2.5 与 8.0 的 Windows 客户端和安卓客户端**，宣称原汁原味无修改，国内网盘分流。适合作为客户端基线。
- 8.0 客户端需要在 `data` 内把四个 BIN 改名为 `real_136.bin`、`adrn_136.bin`、`spr_115.bin`、`spradrn_115.bin` 才能配 8.0 服务端。
- 部分版本必须配 ASSA / STW 外挂登录器才能登录；客户端 IP 通过 `login.lua` + `lua.exe` 或补丁工具改。

### 3.4 代码血统与质量

公开端几乎都出自同一份日文注释的 JSS/华义泄露代码。流传的“商业端”是这条链上的二次改版：

`JSS 原始泄露 → 龙端/longzoro → 螺丝石器 → 椰子 / boxc 大亨 / 17CSA / Yang 8.0 → 各私服魔改`

- **2.5 源**最接近原始结构，`select` 网络模型，代码清晰，适合读懂后自己改。
- **8.0/8.5 商业端**功能多（摆摊、Lua、回炉、VIP），但改动叠加严重、注释缺失、部分端带壳甚至带后门。
- 论坛整包的最大风险是**编译好的二进制**：可能回连作者服务器、限制开服、留后门。能自己编译就自己编译。

## 4. 部署方案矩阵

服务端架构固定：`saac`（账号服，连 MySQL，默认 39202）+ `gmsv`（游戏服，连 saac，游戏端口 1234/9065）+ MySQL（库名 csa，`CSA.sql` 建表）+ 网页注册。

| 方案 | 适用 | 难度 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **A. VMware 一键端** | 单机、快速体验 | ★ | 解压即用，含 GM 工具、注册站、视频教程 | CentOS 6.5 x86 老系统；默认弱口令；公网暴露危险；镜像常带壳 |
| **B. Windows 原生服务端** | 单机、Windows 机器 | ★★ | 不用 Linux；1.82/8.0 有现成 WIN 端 | 版本老、功能少；Win10/11 兼容性差（常需 Win7 兼容模式） |
| **C. Linux 手工端** | 长期自用、小范围联机 | ★★★ | 可控、可备份、可加固 | 需 32 位运行库、老 MySQL、宝塔/VNC，步骤长 |
| **D. 源码编译** | 二次开发 | ★★★★ | 无后门、可改逻辑、可做自己的版本 | 需 CentOS 6.5 32 位 + 老 gcc + MySQL 5.1 开发库；现代 gcc 要改 C99 for 循环和 MariaDB 头文件 |
| **E. Docker / Compose** | 想要可复现环境 | ★★★★ | 一条命令起服、环境隔离、易迁移 | 需自己写 Dockerfile（linux/386 基础镜像 + C99 + MariaDB 客户端库）；公开镜像未必还在 |
| **F. 云服务器 + 内网穿透** | 和朋友玩 | ★★★ | 不占家里网络、固定入口 | 需备案/域名可选；32 位老服暴露公网要限流和改口令 |

### 关键事实

- 服务端是 **32 位 x86 ELF**，`makefile` 直接调 `gcc`、链接 `/usr/lib/mysql/libmysqlclient`。在 64 位系统上必须装 `glibc.i686`、`libstdc++.i686`、32 位 MySQL 兼容库，或用 `-m32` 交叉编译。
- 公开的 Docker 方案见 [《如何用现代的手段编译石器时代的原始码》](https://www.shiqifabu.cc/sq/610.htm)：Debian buster 基础镜像、CMake 加 `-std=gnu99`、`#include <mariadb/mysql.h>` 替换、`mariadbclient` 替换 `mysqlclient`、Compose 里用 alpine 网络命名空间转发 9065、MariaDB 10、`wait-for-it.sh` 控制启动顺序。
- 文章引用 `tonypai/sa25_gmsv`、`tonypai/sa25_saac` 两个镜像；本次网络无法访问 Docker Hub，**镜像是否仍在需自行 `docker pull` 验证**。
- 启动顺序不能反：先 `saac`，再 `gmsv -f setup.cf`；`setup.cf` 里 `acserv=127.0.0.1`、`acservport=39202`、`port=1234`。
- `gmsv` 是老式预申请内存实现，单进程约 2 GB 上限，单世界一实例。

### 你在 macOS 上的现实约束

服务端好办：Docker Desktop 可以跑 `linux/386`（Apple Silicon 上走 QEMU 模拟，性能足够，因为这是 2000 年的 2D 回合制）。

客户端是真正的坎：客户端是 Win32 + DirectDraw，还要配 ASSA/STW 登录器。可行顺序：

1. **Parallels Desktop + Windows 11 ARM**：系统自带 x86 模拟，能跑 32 位 exe；老 DirectDraw 建议加 DDrawCompat/dgVoodoo2。
2. **CrossOver / Wine**：更轻，但老登录器和外挂的兼容性看运气，可能需要单独的 32 位容器和注册表调整。
3. **一台便宜的 Windows 小主机或云 Windows**：最稳，串流/RDP 也能玩，回合制对延迟不敏感。

不推荐在 macOS 上强行用 Android 模拟器配三端服，登录器和脚本生态对不上。

## 5. 推荐路线

按“先能玩、再玩得久”分三段，避免一上来就陷进 8.5 商业端的坑：

### 第 1 段：48 小时内先跑起来（验证可行性）

1. 选 **2.5 版本**，拿 99ds 的 2.5 客户端 + [chenmingbiao/stone-age](https://github.com/chenmingbiao/stone-age) 服务端源码。
2. 服务端用 `debian:buster-slim` 的 `i386` 镜像做 Dockerfile，装 `gcc-multilib`、`libmariadb-dev:i386`、`zlib1g-dev:i386`，按上面的 C99 / MariaDB 补丁编译出 `saac`、`gmsv`。
3. Compose 起 `mariadb:10` + `saac` + `gmsv`，导入建表 SQL，开 9065/1234。
4. 客户端放 Parallels 的 Win11 ARM 里，改 `login.lua` 指向 `127.0.0.1`，配 DDrawCompat 启动。

**这段的目标只是看到登录、建人、进地图。** 跑通后再决定是否换版本。

### 第 2 段：换成你想要的内容版本

- 想要经典 PK 与稳定：留在 2.5，自己加 Lua NPC、任务、掉落。
- 想要 8.0/8.5 的宠物装备、职业、魔域：换 [anson1788/stoneage](https://github.com/anson1788/stoneage) 或 AthenaCN 镜像，服务端编译环境改为 CentOS 6.5 32 位，客户端换 8.0/8.5 并改 DATA 文件名。
- 不要直接拿“商业端”二进制当长期底座；先用它对照功能，再回源码补。

### 第 3 段：小范围联机（可选）

- 云服务器 4C8G 起，Docker 部署，改 DB 口令、只开必要端口、加 systemd 守护和每日 `mysqldump`。
- 对外只暴露游戏端口；注册站加验证码；关闭默认 GM 账号。
- 别急着商业化，先按公益服跑。

### 如果只想“最少折腾”

直接下 8.5 或 8.0 的 **VMware 一键端**（[8.5 版](https://www.gamecbg.com/thread-6048-1-1.html)、[8.0 版](https://www.jiaobenwang.com/1212.html)），VMnet8 设 `192.168.200.0`，按教程启动。代价是 CentOS 6.5、弱口令、镜像不可控；单机玩完全够用。

## 6. 已知技术坑清单

编译/运行：

- `for (int i=...)` 在非 C99 下报错 → CMake 加 `-std=gnu99` 或改声明位置。
- 找不到 `mysql/mysql.h` → 改 `mariadb/mysql.h`，链接 `mariadbclient`。
- 链接失败 → 装 32 位 `zlib`、`libpthread`、MySQL/MariaDB 客户端库；`ldd` 检查缺库。
- CPU 指令集报错（char_base.c）→ 去掉 `-march=pentium4` 一类参数，或换编译机。
- 32 位限制：单进程 2 GB 地址空间，别开超大 `gmsv` 预申请。

数据与配置：

- 全链路 **GB2312**；跨系统改文件必须用 EmEditor/UltraEdit，否则换行符和编码会把配置改坏。
- 8.0 的 DATA 四个 BIN 必须改成 `real_136.bin`、`adrn_136.bin`、`spr_115.bin`、`spradrn_115.bin`。
- 客户端与服务端的 Lua 加密密钥要成对修改，否则登录后立刻断。
- 账号服先起，游戏服后起；`acservport` 与 `saac` 实际端口一致。

安全：

- 一键端默认 `root/123456`、DB `root/woaishiqi`、宝塔 8888 全开，公网必须改。
- 二进制端可能回连作者；抓包或 `strings` 看域名。
- 老 `gmsv` 对畸形包不健壮，公网建议前置防火墙，只放行游戏端口。

## 7. 版权与风险

- 版权链条：JSS → 抵债转给 DigiPark → 华义被判侵权并 2008 年停运 → 胜思/陶朱代理 → 胜思 2016 停运。腾讯《石器时代：觉醒》持有正版授权。
- 私服长期被默许，但已有刑事案例：2012 年螺丝私服主犯被判半年至三年半；2024–2025 年腾讯联合公安打击《石器天空》《部落大乱斗》等，2025 年“剑网 2025”把游戏私服列为重点。
- **自己玩、不收费，风险极低；一旦收费或大规模推广，才进入打击视野。**
- 公开源码基本都标“仅供学习研究，禁止商用”，遵守即可。
