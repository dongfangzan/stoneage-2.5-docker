# 疯狂原始人 Online（2002）专项调研与落地方案

调研时间：2026-10-26
对象：华义国际 2002 年基于石器时代开发的 **纯 PK 分支端游**（非电影 IP，非 2019 手游）
目标：自己搭一台单机/小范围私服，还原原版 PK 体验

---

## 0. 结论先行

**这是一款“能复刻，但要先考古”的游戏。**

- 服务端有货但很稀有：WeLoveSA 论坛存有“疯狂原始人 2.0 服务端 + 配套 DATA + 登录器”整包（tid=2514，发布于 2013 年 11 月之前），需要注册、登录、2 石币。2012-12 就有人在藏宝湾求端且无人给链，2014 年论坛回复已是“现在这个不好找了，估计没有了”。
- 客户端没货：官方客户端早已绝迹，官网 `fkysr.com` 已死，公开搜索找不到可用下载。这是当前唯一的硬缺口。
- 没有公开源码：网上没有 GitHub 仓库或源码包；论坛只有二进制服务端整包。
- 引擎同源但版本更早：和石器共用 `saac`（账号服）/`gmsv`（游戏服）/MySQL 架构，但 2.0 早于 2.5，协议、DATA、DB 结构都不同，**不能拿 2.5/8.0 的服务端直接配 2.0 客户端**。
- 原版客户端是 Win95/98/2000 + DirectDraw 640×480 256 色，在 Apple Silicon Mac 上必须走 Windows 虚拟机，CrossOver 只能算备选。

**因此路线不是“下载一键端”，而是：先拿 2.0 服务端包 → 从收藏者手里找 2.0 客户端 → 在隔离的旧版 Windows 环境里复刻。** 但服务端和客户端两样都稀有，**建议不要干等**：先用 2.5 源码搭一台 PK 规则服把链路跑通（方案 C），同时并行求档。今天的“疯狂原始人”服大多就是 2.5 换皮，不完全是原版，但能先玩起来。

## 1. 游戏事实

| 项目 | 内容 |
| --- | --- |
| 开发/运营 | 华义国际（Wayi），基于石器时代 IP 自行开发 |
| 性质 | 把石器时代的 PK 战斗单独拆出来的纯竞技网游，无练级、无打怪、上线即 PK |
| 上线 | 2002-05-01，当天同时在线破 6000 |
| 停服 | 2004-07-30（运营约两年三个月） |
| 版本 | 1.0（2002-05-01）；**2.0（2003-01-12）**；2013 年后私服圈出现所谓“3.0”，非官方版本号 |
| 2.0 变化 | 新增蒙奇、鲁比、3-3 魔法戒指等宠物/道具；开放青龙 MP 攻击、蛙类恶毒攻击、鲨鱼转属攻击等宠物技能；新增战绩面板（总战斗数、总胜场、当前连胜、最高连胜） |
| 人物规则 | 创建角色可选 12 种形象（男女各 6，各 4 色），分属阿布族、巴拿族、达那族；**500 点自由配点，每场 PK 后可重配** |
| 场景 | 玛雷菲雅村，四大竞赛家族，光明精灵王设定 |
| 官方配置 | Win95/98/Me/2000；Pentium II 200MHz；32MB 内存；850MB 硬盘；640×480 256 色；DirectDraw 2MB 显存；DirectX 7.0；必须联网 |
| 安装路径 | 默认 `C:\Program Files\Waei\疯狂原始人\`，光盘 `SETUP.EXE` |

> 注意：2.0 的“500 点随改随配 + 战绩统计”是它和石器时代最大的机制差异，也是复刻时必须保留的核心。今天很多打着“疯狂原始人”旗号的服其实只是 2.5 无职业 PK 服，配点仍是 20 点，不是原版。

## 2. 私服史（说明资源为什么长这样）

这条时间线解释了今天能捡到什么：

- **2008-06**：大陆已有私服 `fk.freedoms.com.cn`，繁体玩家要挂 Microsoft AppLocale 才能跑简体客户端（Mobile01 帖）。
- **约 2010–2014**：台港私服活跃，巴哈姆特“瘋狂原始人”哈啦板（bsn=24883）有《白色凍土》《溶火高地》《無盡高原》《閃光沙漠》等服，玩家互相拉人、收账号。
- **2013**：出现标“疯狂原始人 3.0”的私服宣传片，官网域名 `fkysr.com`。
- **2022**：仍有“石器SA私服：疯狂原始人 一机多控”这类视频。
- **2026**：Facebook 石器群还在开“石器尼斯大陸之瘋狂原始人”二区——但这类多是 **2.5 换皮/规则服**，不是原版客户端。

结论：原版服务端在私服圈内一直小范围流传，但客户端只在当年玩家硬盘和光盘里，没有形成公开下载源。

## 4. 技术架构与和石器的差异

相同：

- `saac` 账号服 + `gmsv` 游戏服 + MySQL 三件套。
- `saac` 先起，`gmsv` 通过 `acserv=127.0.0.1:39202` 注册，游戏端口另开。
- 32 位 Linux ELF，老 gcc 编译，GB2312 编码。
- 客户端改 IP 走 `login.lua`/补丁工具。

不同（决定了不能混用）：

- 2.0 没有 Lua/ABLUA 体系，NPC 与任务用 `.create` 文本脚本。
- 没有职业、装备位、转生、融合宠，DB 表更少。
- 配点上限 500 且可变，登录流程直接进 PK 大厅而非地图打怪。
- DATA 只包含 PK 地图、12 形象、PK 宠物池，比石器小得多（官方全量 850MB，含光盘动画）。
- 登录器带大厅/房间/观战逻辑，不是石器的选线登录。

> 因此：**用 2.5 服务端 + 2.0 客户端是行不通的**，必须用包里的 2.0 服务端和 DATA。

## 5. 部署方案

> **当前已落地：** 本机已经用 2.5 源码 + `linux/386` 容器跑通 `saac` / `gmsv` / MariaDB，游戏端口 `127.0.0.1:9065` 监听中，GM 账号 `gm/gm`，2.5 客户端包（496 MB）已下载。操作见 [RUN-2.5.md](./RUN-2.5.md)。这套是方案 C 的第一步，等原版 2.0 资源到位再替换。

### 方案 A：原版复刻（终极目标）

| 层 | 选型 |
| --- | --- |
| 服务端宿主 | x86_64 Linux VM（UTM/Parallels）跑 CentOS 6.5 **32 位**，或 Docker `i386/debian:buster` |
| 编译 | gcc 4.x + `-m32`，链接 32 位 `libmysqlclient`、`zlib`；现代 gcc 需补 C99 声明 |
| 数据库 | MySQL 5.1（优先，和端同期）或 MariaDB 10 + 头文件/库替换 |
| 客户端宿主 | **Windows 98 SE 或 Windows XP SP3 虚拟机**（VMware Fusion / UTM / Parallels） |
| 图形 | 装 DirectX 7/9，配 dgVoodoo2 或 DDrawCompat 解决现代显卡的 DirectDraw 问题 |
| 网络 | 虚拟机 Host-Only/NAT，服务端与客户端同一网段；单机不需要端口映射 |
| 隔离 | 服务端和客户端都断外网，避免老系统被扫 |

优点：唯一能还原原版配点、大厅、战绩、宠物池的路线。
缺点：客户端的获取是前置阻塞；Win9x/XP 虚拟机需要额外配置。

### 方案 B：2.5 规则服（先行动手）

用公开的 2.5 源码（[chenmingbiao/stone-age](https://github.com/chenmingbiao/stone-age)）搭服，改 Lua 实现：

- 建号即 500 点、可重复洗点；
- 只开 PK 地图，关闭野外遇怪；
- 移除职业、转生、装备位；
- 登录直接传大厅，加战绩统计脚本。

优点：今天就能开工，客户端（99ds 的 2.5 端）和工具链齐全。
缺点：不是原版画面和 UI，宠物池/技能要自己补，工作量在脚本侧。

### 方案 C：混合（推荐执行顺序）

**默认按 C 走**：先用方案 B 把“能玩”跑通，验证服务端编译、DB、登录链路；同时并行求 2.0 服务端包和客户端。拿到原版资源后再切方案 A，B 的运维经验（守护、备份、加固）直接复用。这样不会因为等档而停摆。

### macOS 客户端注意事项

- 原版客户端是 32 位 Win9x 程序，**CrossOver 在 Apple Silicon 上跑 DirectDraw 老程序成功率一般**，且登录器常带壳。
- 首选 Windows 98 SE/XP 虚拟机；VMware Fusion（Apple Silicon 版）或 UTM 都可以，分配 1GB 内存、4GB 磁盘、开启 3D 加速。
- 显示用 dgVoodoo2 包一层，分辨率固定 640×480 或 800×600。
- 如果登录器需要 IE/ActiveX，XP 虚拟机里装 IE6 兼容模式。

## 6. 执行清单

### 阶段 0：拿资源（与阶段 1 并行）

- [ ] 注册 WeLoveSA，签到/回帖攒 2 石币，购买 tid=2514。
- [ ] 解包，记录文件清单、大小、哈希；确认包含 `saac`、`gmsv`、`DATA`、`登录器`、建库 SQL、配置文件；若只有二进制，先 `strings` 查回连域名。
- [ ] 同时在 WeLoveSA、巴哈 bsn=24883、百度贴吧、藏宝湾发求客户端/求整包帖，标题写明“2002 华义端游、非手游、求 2.0 客户端或光盘镜像”。
- [ ] 每拿到一个客户端，先比对 DATA 文件名和版本号，再谈运行。
- [ ] 并行启动阶段 1 的 2.5 环境，不等档。

### 阶段 1：服务端

- [ ] 建 CentOS 6.5 i386 虚拟机（或 `i386/debian:buster` 容器）。
- [ ] 装 gcc、make、zlib-devel.i386、MySQL 5.1 client/server/devel。
- [ ] `make depend && make`，产出 `saacjt`、`gmsvjt`；记录所有编译错误。
- [ ] 建库、导 SQL、改 `acserv.cf`/`sql.cf`/`setup.cf`。
- [ ] 先起 `saac`，确认 39202 监听；再起 `gmsv`，确认载入 DATA 无报错。

### 阶段 2：客户端

- [ ] Win98SE/XP 虚拟机，装 DirectX 7/9 和 dgVoodoo2。
- [ ] 客户端全目录放入，改 `login.lua` 指向服务端 IP。
- [ ] 用包内登录器启动，先进大厅，再进房，最后进战斗。
- [ ] 逐项验证：12 形象、500 配点、洗点、宠物列表、技能、战绩面板。

### 阶段 3：固化

- [ ] 服务端写 systemd/守护脚本，每日 `mysqldump`。
- [ ] 客户端目录打包备份，虚拟机做快照。
- [ ] 若联机：只放行游戏端口，改默认 DB 口令，限制连接数。

## 7. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 客户端找不到或 DATA 不匹配 | 整个方案 A 卡死 | 并行做方案 B；求档时明确要 2.0 原版而非 2.5 换皮 |
| 服务端包是二次改版/带壳 | 后门、回连、限制 | `strings` 找域名；断网跑；必要时对照 2.5 源码审计 |
| Win9x 虚拟机装不上现代 CPU | 客户端起不来 | 用 XP SP3 代替；UTM 选 x86_32；关掉 SMP |
| 老 gmsv 内存 2GB 上限 | 人数上限低 | 只自己玩，不做公开服 |
| 版权 | 不能商用 | 自用即可；收费前先看腾讯/网石的打击动向 |
