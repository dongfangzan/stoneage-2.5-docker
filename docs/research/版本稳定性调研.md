# 石器时代服务端：稳定性与 bug 调研

调研时间：2026-10-26
目标：在公开可得的端里，找 bug 最少、最适合长期单机/小范围运行的一个
方法：论坛口碑 + 代码血统 + 实际编译运行验证

---

## 结论

**没有一个“官方认证最稳”的版本，但社区共识很明确：longzoro（后期 AllBlues）的 2.5 商业代码是事实标准。**

WeLoveSA 老玩家在技术史讨论里原话：

> 基本上现在大多数公开的石器服务端，都是由 longzoro（后期为 AllBlues）的商业代码所开发……底下这个 longzoro 服务端代码就已经很完整，而且几乎没 bug/后门了，直接拿来用就可以。

另一位补充：“商业端摊出来就是一个很完美的 code。”

**所以答案不是换一个神秘版本，而是：留在 longzoro 2.5 这条线上。** 我们当前跑的 `chenmingbiao/stone-age` 正是这条血统（`saac/main.c` 里 `Copyright 2006 龙王`、握手前缀 `longzoro-`），而且已经在本机编译、启动、握手成功。

如果要在“完整度”上再加一档，用 **轻石器双端源码** 补客户端、建库 SQL、cf 配置和 Lua；它的服务端同样被认出是“龙端改”。

---

## 判断标准

标题里的“稳定”“完美”“无 bug”基本不可信，原因：

- 资源站标题是 SEO，不是测试报告。8.5 一键端标题写“稳定无外挂”，回帖只有“666”。
- 一键端/淘宝端多为加壳二进制，来源不明，可能回连、留后门。
- “功能多”和“稳定”负相关：8.x 每多一个系统（职业、装备位、回炉、魔域）就多一片 bug 面。

真正可用的信号只有三个：**代码血统、社区长期口碑、有人实际编译/运行成功**。

## 证据

### 支持 longzoro 2.5

- WeLoveSA 技术史帖（2019）：longzoro 代码“几乎没 bug/后门”，公开端大多是它的衍生；另一支 SMO 代码已停止维护。  
  <https://lab.welovesa.com/viewthread.php?action=printable&tid=3536>
- 当前仓库就是 longzoro 系：`server-2.5/saac/main.c:230` 的 `longzoro-%s-%d`、`:382` 的 `Copyright 2006 龙王`。
- 本地实测：32 位容器内编译通过，`saac`/`gmsv` 启动、握手、载入 700 张地图与 4952 个 NPC，无崩溃。

### 支持“2.5 比 8.x 稳”

- 2.5 系统最少（无职业、无装备位、无回炉、无魔域），bug 面最小。
- 现存活服里 2.5 无职业 PK 是主流，8.5 带职业次之。
- 8.0 服主自述“该版本可扩展性不强，玩法单一”，已从 8.0 转回 2.5。  
  <https://www.sqdll.com>
- 玩家总结：2.5 缺后续内容，8.5 带职业不平衡。  
  <https://jingyan.baidu.com/article/93f9803f4b2b55e0e56f557c.html>
- 8.0 单机版要靠补丁修人龙、虎王、9 尾狐、2D 虎分身等技能 bug，说明 8.x 端遗留问题多。  
  <https://www.7chaowan.com/101241.html>

### 轻石器源码的定位

- 246 石器博客的描述：全套客户端 + 服务端源码、配套数据库表、cf 配置、双端 Lua、支持 LNS/ablua/光环/称号，市场称之为“轻石器源码”。  
  <https://www.246sa.com?cat=9>
- WeLoveSA 帖里版主评价“源码很完整”，回帖者认出服务端“應該是龍端改”。  
  <https://www.lab.welovesa.com/viewthread.php?tid=3481>
- 反面：2018 年发布后没人贴出成功编译报告；2026-10 仍有“轻石器客户端源码编译后开启报错”的求助。

### 椰子 / 螺丝 / 大亨

- 椰子端流传广（“价值 1800”），但回帖指出“只有到 2.5 的任务，3.0 之后都没有，几个小时玩完”。  
  <https://www.iopq.net/thread-17118551-7-1.html>
- 螺丝源码被称为“能编译能架设极品源码”，但帖子没人确认配套客户端，也没有稳定性反馈。  
  <https://www.lab.welovesa.com/viewthread.php?tid=3466>
- 大亨（boxc）商业端功能全，但同样是二进制整包为主，公开的只有架设教程。

## 排序

| 档 | 对象 | 理由 | 怎么用 |
| --- | --- | --- | --- |
| **S** | **longzoro / AllBlues 2.5 商业代码**（当前 `server-2.5`） | 社区公认“几乎没 bug/后门”，血统清晰，已实测编译运行 | 作为唯一底座，继续加固 |
| **A** | **轻石器双端源码** | 最完整的公开包：客户端 + 服务端 + 建库 SQL + cf + 双端 Lua；同为龙端改 | 只取客户端、SQL、Lua、配置，服务端仍用 S |
| **B** | 2.5 服务端精简源码 | 去 MySQL、改 UTF-8、可在 gcc 编译，但功能被裁剪 | 想要极简代码阅读时参考 |
| **C** | 螺丝石器源码 | 名气大、被称“极品”，但老、无客户端、无运行报告 | 只作代码对照 |
| **C-** | YANG 8.0 | 长期维护、帖子 30 万浏览，但 8.0 内容与 bug 面更大 | 明确要 8.x 时才用 |
| **D** | 各类 8.5 / 淘宝 / VM 一键端 | 开箱即用，但二进制不透明、来源杂、标题党 | 只做快速试玩，不做长期底座 |

## 推荐组合

1. **服务端**：保留当前 longzoro 2.5，继续用已经跑通的 32 位容器方案。
2. **客户端与数据**：如果现有 2.5 客户端够用就不换；需要更完整资源时，从轻石器包取客户端、`CSA.sql` 风格的建库脚本和 Lua，逐项比对 DATA 版本。
3. **规则**：2.5 无职业 PK，关掉野外遇敌，保留最少系统。
4. **加固**：改默认口令、只绑本地、每日备份、定期 `strings` 查二进制回连。

不要为了“功能多”换 8.5；也不要直接拿一键端的二进制当长期底座。

---

## 避坑清单

- 标题写“完美/无敌/最全”的，优先看回帖有没有人真跑起来。
- 加壳的 `gmsvjt.exe`/`saacjt.exe`：先断网跑，`strings` 查域名。
- 只给服务端不给客户端的包：大概率配不上 DATA。
- 8.0/8.5 的“商业端”：功能越多，修的补丁越多，单机没必要。
- 需要虚拟机密码 `123456`、宝塔 `8888` 全开的镜像：公网前必须改。

## 置信度说明

这是**论坛口碑 + 血统判断 + 一次真实编译运行**，不是压测或代码审计。longzoro 被公认稳定，但“几乎没 bug”是 2019 年一位老玩家的判断，不等于零 bug；我们本轮已经修掉 3 处高危和若干越界写法。真要长期跑，仍应自己做备份和最小化暴露。
